Beginner Coding and AEM Authoring Guide

This guide is made for someone who is starting from basic coding and wants to understand the project structure, code quality improvement areas, and authoring plan for this AEM site.

1) Beginner JavaScript code snippets with explanations

Example 1: Variables and conditions

let age = 22;
let name = "Aman";
let isStudent = true;

if (age >= 18) {
  console.log(name + " is an adult.");
} else {
  console.log(name + " is not an adult.");
}

Explanation: let stores values. if checks a condition and runs code when true.

Output:

Aman is an adult.

Example 2: Function with return value

function greet(personName) {
  return "Hello, " + personName + "!";
}

console.log(greet("Priya"));
console.log(greet("Rohit"));

A function is reusable code.

Example 3: For loop

for (let i = 1; i <= 5; i++) {
  console.log("Number:", i);
}

The loop repeats until i reaches 5.

Example 4: Array and map

let marks = [80, 90, 70, 95];
let doubled = marks.map((mark) => mark * 2);
console.log(doubled);

map() transforms each item in an array.

Example 5: Object

let student = {
  name: "Karan",
  age: 21,
  course: "Computer Science"
};

console.log(student.name);
console.log(student["age"]);

Objects store data as key-value pairs.

Example 6: Find largest number

let numbers = [12, 5, 98, 34, 76];
let maxNumber = numbers[0];

for (let i = 1; i < numbers.length; i++) {
  if (numbers[i] > maxNumber) {
    maxNumber = numbers[i];
  }
}

console.log("Largest number is:", maxNumber);

Example 7: Reverse a string

function reverseString(str) {
  let reversed = "";
  for (let i = str.length - 1; i >= 0; i--) {
    reversed += str[i];
  }
  return reversed;
}

console.log(reverseString("hello"));

2) Code quality analysis of the project blocks

I reviewed the block folders and project patterns. Overall, the codebase is a good learning project with several helpful patterns, but it needs improvement in maintainability, reusability, and production quality.

What is already good

  • Block-based structure is clean and consistent.
  • Project uses modular JavaScript block files.
  • Some files use safe DOM creation patterns.
  • Several blocks follow the AEM authoring pattern well.
  • Use of optimized image creation is good.

Main quality gaps

  • Hard-coded demo data in product and cart blocks.
  • Too much inline styling.
  • Global state and window event side effects.
  • Weak error handling.
  • Accessibility gaps.
  • Duplicate logic across blocks.

3) Block-by-block improvement areas

  • Header: reduce inline CSS, split logic, improve accessibility.
  • Product details: move data to author config, reduce hard-coded values.
  • Product card: use real data, graceful fallback.
  • Search: improve filter state and accessibility.
  • Faceted search: split large logic into helpers.
  • Cards / accordion / tabs: focus on semantics and responsive behavior.
  • Footer / fragment: improve stable link handling and fallback states.
  • Localized CTA / personalized fragment: validate audience data and handle network failures.

4) Page authoring plan for document authoring

Main page types to create

  1. Home page - hero, cards, stats, testimonials, CTA, FAQ
  2. Product listing page - search, filters, cards
  3. Product detail page - product details, related cards, tabs
  4. About page - columns, quote, stats, tabs
  5. Blog/content page - search and cards
  6. Contact/support page - FAQ, columns, embeds

5) What to add on each page

  • Clear heading hierarchy
  • One goal per page
  • Strong CTA text
  • Consistent spacing and visuals
  • Fallback content when a field is missing
  • Accessible keyboard and semantic structure

6) Final advice

Focus on logic, reading code line by line, testing small examples, and improving readability. For this project, the best improvement areas are: reduce hardcoded values, clean inline styles, improve accessibility, add graceful fallback states, and separate large logic blocks into reusable functions.
